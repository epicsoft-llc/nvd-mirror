Datafeed

Point Dependency-Check at the mirror

The NVD data as gzipped JSON, one file per year plus the recent changes. Dependency-Check downloads what is new – over plain HTTP, without an NVD API key. 

dependency-check --updateonly \
  --nvdDatafeed https://nvd.epicsoft.one/nvdcve-{0}.json.gz

{0} stands for the year. Files: nvdcve-2002.json.gz … nvdcve-<year>.json.gz, nvdcve-modified.json.gz and cache.properties.

gunzip -c dependencycheck-mysql.sql.gz | mysql dependencycheck

PostgreSQL

@PG_ENGINE@ · @PG_SIZE@

Plain SQL from pg_dump, without owner and grants. It uses \restrict, so import it with a current psql.

dependencycheck-postgres.sql.gz · sha256

createdb dependencycheck
gunzip -c dependencycheck-postgres.sql.gz \
  | psql -d dependencycheck

The files fit Dependency-Check @DC_VERSION@ (database schema @SCHEMA@). Accounts and grants are not part of the SQL dumps – set up the database as in Using a Database Server. db.json lists versions, counts and checksums.

The databases are not available at the moment. The datafeed is not affected.

How it works

Built in the open, every night

From the NVD

vulnz fetches the changes from the NVD API and writes the datafeed. Before anything is published, every yearly file must be a valid gzip file.

Checked databases

Dependency-Check loads the new feed into H2, MariaDB and PostgreSQL from scratch. All three must agree with each other and with the feed, and the MySQL import is tested as well.
